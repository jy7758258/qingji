### 0.4 已确认的产品决策

1. **形态（已确认）**：只做 **Web 网页**，响应式设计；**必须兼容手机浏览器**（Safari / Chrome / 微信内置浏览器）。不做原生 App、不做微信小程序。
2. **账号（v1.1.1 新增）**：引入**用户名 + 密码**的注册与登录；不收集邮箱、手机号，不接微信 / Apple / Google 等第三方登录，不做短信验证码。
3. **市场**：中国大陆用户为主，简体中文、人民币（CNY）。
4. **数据**：账目仍以浏览器本地存储为主，按账号隔离；**v1.1.1 的登录不等于云同步**，换设备登录不会自动带回账目，仍需导出/导入备份。云同步放到 v1.2 评估。
5. **商业**：v1.1.1 免费，无广告、无内购。
6. **架构（v1.1.1 变化）**：新增轻量认证后端，仅存储用户名、密码哈希、恢复码哈希与会话；**不存储任何账目、分类、备注**。前端仍为可静态部署的 Web 应用。
7. **部署**：静态站点 + 认证 API；域名与托管方式待定（见第 13 章）。

> **关键影响**：账号解决的是「身份与本地账本归属」，不是「数据上云」。v1.1.1 仍需把「导出备份 / 导入恢复」作为 P0；清除浏览器数据或换设备后，仅登录无法找回账目。此外，iOS 上「添加到主屏幕」的网页与 Safari 可能使用彼此隔离的存储，切换入口前必须先备份。

### 0.5 v1.1.1 变更摘要

- **新增账号**：用户名 + 密码注册、登录、自动登录、退出；不收集邮箱 / 手机号，不做验证码与第三方登录。
- **新增轻量认证后端**：只存用户、密码哈希、恢复码哈希与会话，**不存账目**。
- **账本按账号隔离**：每账号使用独立 IndexedDB；v1.0 本机账本支持一次性绑定迁移。
- **登录不等于云同步**：换设备需登录 + 导入备份；云同步仍留在 v1.2 评估。
- **安全与找回**：Argon2id / bcrypt、HttpOnly Cookie、限流、CSRF、统一错误；恢复码为 P1，建议同期上线。
- **不在本期**：邮箱 / 手机号注册、短信验证码、第三方登录、游客模式、多设备同步、家庭共享。

## 1. 产品概述

### 1.1 一句话定位

**「轻记」是一个打开网页就能用的个人记账工具——不用下载，注册只需用户名和密码，3 秒记一笔，月底看清钱花在了哪里。**

### 1.2 背景与问题

记账类产品的核心矛盾不是「功能不够」，而是**用户记不下去**：

- 下载、注册、引导、选分类、填金额、选账户，动辄 30 秒以上，高频场景下用户很快放弃。
- 统计报表越做越复杂，用户看完仍不知道「下个月该改什么」。
- 广告、社区、理财导流让工具变重，隐私顾虑增加。
- 原生 App 的安装门槛，让「偶尔想记一下」的用户直接流失。

Web 形态的机会：**零安装、一个链接即用**，分享和跨平台成本最低。
Web 形态的代价：浏览器数据不可靠、无系统级推送、移动端输入体验受限——这些必须在产品设计中被正视，而不是回避。

v1.0 没有账号，账本只属于「这台设备上的这个浏览器」：同一台设备换人使用、换设备、清缓存，都无法区分「这是谁的账本」。v1.1.1 引入账号，解决三件事：

- **身份**：知道账本属于谁，为未来云同步建立用户主体；
- **隔离**：同一浏览器切换账号，各自只看到自己的账本；
- **保护**：用密码阻止他人随手打开账本。

但账号也会带来新的摩擦与风险：忘记密码、撞库、密码泄露、用户误以为「登录 = 数据上云」。因此 v1.1.1 坚持**只收用户名和密码**，把账号做成一层轻量的门锁，而不是收集个人信息的入口。

用户真正需要的不是「一个财务系统」，而是：**记录足够省事，回头看得懂，数据拿得走。**

### 1.3 产品目标

| 层级 | 目标 | 衡量方式 |
| --- | --- | --- |
| 用户目标 | 打开链接后 60 秒内完成注册并记下第一笔；日常 3 秒一笔；月底 1 分钟看懂支出结构 | 注册完成用时、首次记账用时、单笔耗时 |
| 产品目标 | 让记账成为可持续的日常习惯 | 周记账 ≥5 天的用户占比（北极星指标） |
| 账号目标 | 用最少信息建立账号，登录后只看到自己的账本 | 注册完成率、登录成功率、会话保持率 |
| 技术目标 | 手机浏览器可用、账号安全、数据不丢、可迁移 | 登录 P95、认证失败率、备份/恢复成功率、数据丢失投诉数 |
| 商业目标（远期） | 验证「极简工具」的付费意愿 | 后续版本再定义 |

### 1.4 非目标（v1.1.1 明确不做）

- ❌ 原生 iOS / Android App、微信小程序
- ❌ 邮箱 / 手机号注册、短信验证码、第三方登录（微信 / Apple / Google）
- ❌ 云同步、多设备实时同步（v1.1.1 不做；v1.2 再评估）
- ❌ 游客模式（存量 v1.0 本地账本只作为一次性迁移入口）
- ❌ 社区、论坛、账单晒单
- ❌ 理财推荐、贷款、信用卡导流、广告
- ❌ 自动抓取银行/支付流水
- ❌ 家庭共享账本、多人协作
- ❌ 发票管理、报销流程、复杂资产管理
- ❌ 系统级推送通知、后台自动记账

### 1.5 产品原则

1. **低门槛**：打开即用；注册只需用户名和密码，不收集手机号 / 邮箱，不强制验证码。
2. **摩擦最小**：任何一次记录，操作步数与输入字符数都要被质疑。
3. **默认即合理**：金额之外的一切字段都有智能默认值，用户可改可不改。
4. **本地优先**：账目默认不上传（认证服务只存账号信息）；无网络时，已登录且已加载的账本仍可记账。
5. **数据可携带**：导出、导入、清空都是一等公民，绝不锁定用户。
6. **诚实**：明确告知数据存储位置与风险，不制造「登录就自动同步」的错觉。
7. **克制与尊重**：不制造焦虑、不用红色惊吓、不频繁打扰；文案中性、不评判。
8. **温柔但不幼稚**：粉嫩配色负责降低压力，深色文字与留白负责清晰；可爱不能牺牲可读性和财务工具的可信度。
9. **账号克制**：账号只为身份、归属与保护存在；能用用户名 + 密码解决，就不多要一项个人信息。

## 2. 用户与场景

### 2.1 目标用户

| 维度 | 描述 |
| --- | --- |
| 核心人群 | 22–35 岁上班族，一二线城市，有稳定收入 |
| 特征 | 想控制消费但没时间学习复杂工具；用过记账 App 但没坚持下来 |
| 设备 | iPhone / Android 手机浏览器为主，偶尔使用电脑浏览器 |
| 入口习惯 | 微信里点开链接、浏览器书签、添加到主屏幕的图标 |
| 动机 | 「想知道钱花哪了」「想存下钱」「不想再月光」 |
| 阻碍 | 记录麻烦、分类太多、报表看不懂、担心隐私、怕数据丢、不想为记账交出手机号 |

### 2.2 用户画像

**小林，27 岁，互联网运营，月薪 1.2 万**
- 每天 3–8 笔消费，主要是三餐、通勤、咖啡、网购。
- 曾下载过 3 款记账 App，最长坚持 11 天；不想再为记账装一个 App。
- 月底看到信用卡账单会焦虑，但不知道从哪省。
- 原话：「我不是不想记，是每次都要点好多下，烦。也别让我为了记账填手机号。」

### 2.3 核心场景（Jobs to Be Done）

| 场景 | 用户任务 | 产品回应 |
| --- | --- | --- |
| 注册 | 想用最简单的账号保护账本 | 只填用户名 + 密码，60 秒内完成；不收手机号 / 邮箱 |
| 登录 | 打开网页后继续自己的账本 | 用户名 + 密码登录；默认 30 天自动登录 |
| 即时记录 | 刚付完钱，想马上记下来 | 登录后打开即用、默认值齐全、3 秒保存 |
| 补记 | 晚上想起白天漏记了几笔 | 快速切换日期、记住上次分类 |
| 月末复盘 | 想知道这个月钱花哪了 | 一页看懂：总额、分类占比、环比 |
| 数据安心 | 换手机、清缓存、担心丢失 | 一键导出备份、导入恢复、备份提醒 |
| 多端使用 | 手机上记、电脑上看 | v1.1.1 通过登录 + 导出/导入迁移；**不自动同步** |
| 共用设备 | 和家里人共用浏览器，不想互相看到账本 | 退出登录；不同账号使用独立本地账本 |
| 忘记密码 | 想找回自己的账号 | 恢复码找回（P1）；没有恢复码则无法自助找回 |

### 2.4 关键用户旅程

**首次使用（目标 ≤90 秒进入记账）**
```
点开链接 → 注册页 → 用户名 + 密码 + 确认密码 → 自动登录 →
（如有 v1.0 本机账本）选择绑定到当前账号 → 进入明细 → 记第一笔
```
- 注册只要求用户名和密码，不要求邮箱、手机号、验证码。
- 不做长问卷、不要求头像/昵称、不申请无关权限。
- 注册成功后立即进入账本，不强制阅读教程。

**老用户升级（v1.0 → v1.1.1）**
```
打开网页 → 检测到未绑定账号的本机账本（X 笔）→ 注册或登录 →
注册：提示「把本机 X 笔账目绑定到 @username？」→ 确认 → 原子迁移 → 进入账本
登录已有账号：提示本机账本将保留为未绑定状态 → 可先导出备份
```
- 迁移前自动导出一次旧账本备份；迁移后校验账目条数一致。
- 任何情况下不得删除旧账本，直到用户确认。

**日常记账（目标 ≤6 秒）**
```
打开书签/主屏幕图标 → 自动登录（30 天内）→ 点「+」→ 输入金额 → 分类已预选 → 保存 → toast + 撤销
```
- 手机端为全屏记账页；桌面端为居中弹窗。
- 浏览器返回键应关闭记账页，而不是退出站点。
- 会话过期时回到登录页，登录后回到原页面。

**换设备 / 迁移（目标 ≤3 分钟）**
```
旧设备：我的 → 数据与备份 → 导出完整备份（JSON）
新设备：打开网页 → 登录 → 首次进入提示「此设备还没有账本」→ 导入备份 → 预览确认 → 恢复
```
- 登录本身不会带回数据；必须导入备份。页面要在登录后明确说明这一点。

**忘记密码**
```
登录页 → 忘记密码 → 用户名 + 恢复码 + 新密码 → 重置成功 → 所有旧会话失效
```
- 未保存恢复码的用户，页面明确提示无法自助找回；建议联系支持，但不承诺可找回。

**月末复盘（目标 ≤1 分钟）**
```
打开统计 → 看本月支出与环比 → 看分类 Top5 → 点击分类下钻 → 发现异常 →
（v1.1）为该分类设置下月预算
```

## 3. 竞品与差异化

| 产品 | 优势 | 短板 | 我们的取舍 |
| --- | --- | --- | --- |
| 随手记 | 功能全、账本模板多 | 重、广告多、学习成本高 | 只做个人日常账，做减法 |
| 鲨鱼记账 | 轻量、上手快 | 统计浅、商业化重、需安装 | 更克制的商业化 + 更实用的洞察 |
| MoneyWiz | 专业、多账户多币种 | 复杂、付费高、本地化弱 | 面向普通人的「够用」 |
| Excel / 备忘录 | 自由、零成本、网页可用 | 无统计、易出错、难坚持 | 结构化 + 自动化 + 低摩擦 |
| 网页版记账工具 | 免安装 | 多为桌面优先、手机体验差 | **移动浏览器优先**的响应式体验 |

**差异化定位**：市面上不缺功能全的记账产品，缺的是「打开就能记、不费劲、数据拿得走」的工具。轻记以**零安装门槛**、**记录效率**和**数据主权**为核心竞争力。

大多数记账产品用手机号、微信或 Apple 登录；轻记 v1.1.1 只保留**用户名 + 密码**，主动放弃手机号/邮箱带来的找回便利，换取更低的注册门槛和更少的个人信息采集。代价必须由**恢复码、清晰的备份引导和安全的密码策略**来补。

## 6. 功能需求详述

### 6.0 视觉与体验基调：粉嫩、可爱、但不幼稚

**关键词**：奶油粉、樱花、软糯、圆润、轻松、温柔。
**目标**：让记账这件事看起来没有压力。粉色负责情绪，深色文字负责清晰；可爱服务于「愿意打开」，不能牺牲「看得清」。

**用色比例（60–30–10）**
- **60%** 暖白 / 奶油粉背景：留白与呼吸感。
- **30%** 白色卡片与内容区：承载数据。
- **10%** 粉色与辅色：品牌、按钮、状态、图表。
- 粉色是点缀，不是墙纸；整屏高饱和粉会显得廉价、刺眼，也会削弱财务数据的可信度。

#### 6.0.2 字体与数字

- **中文正文**：`"PingFang SC", "HarmonyOS Sans SC", "Noto Sans SC", system-ui, sans-serif`，优先系统字体，保证加载速度。
- **数字 / 金额**：优先 `"Nunito"`、`"Baloo 2"` 等圆体数字，**本地自托管、按字符子集化（≤30KB）**，加载失败回退系统字体；不得依赖境外字体 CDN。
- **字号**：
  - 页面主金额：移动端 40–44px，桌面端 48px，字重 700；
  - 列表金额：16px，字重 600；
  - 正文：16px，行高 1.5；
  - 辅助信息：13–14px；
  - 最小字号 12px，不使用更小字号承载关键信息。
- **数字对齐**：金额与统计数字使用 `font-variant-numeric: tabular-nums`，避免跳动。
- 标题字重 600–700，正文 400–500；不使用 Comic Sans 等过度幼稚的字体。

#### 6.0.3 形状、图标与插画

- **圆角**：按钮胶囊形（999px）；卡片 20px；输入框 16px；弹窗 24px。
- **描边与阴影**：1px `#F2D7E1` 弱描边；卡片阴影带粉色 tint（`rgba(199,62,109,0.08)`），不使用厚重灰阴影。
- **图标**：24px 线性图标，1.8px 描边，圆角端点；选中态可填充粉色。分类图标放在 40px 淡彩圆形底上，底色从图表色板的浅色变体取，不直接使用高饱和色。
- **默认分类图标**：统一使用 SVG 图标库；线框中的 emoji 仅作示意，正式界面不混用 emoji 与线性图标。
- **品牌形象「小桃」**：一颗粉色小桃子，简单表情，最多 3 种状态（开心、鼓励、抱歉）。仅出现在空状态、首次引导、保存成功等情绪节点，每屏最多 1 个。
- **插画风格**：扁平、圆润、柔和，可使用轻微颗粒质感；不使用廉价 stock 照片，不堆砌爱心、星星、蝴蝶结等装饰元素。
- **动效**：160–240ms，`ease-out`；保存成功可做一次轻微缩放 + 对勾；列表插入淡入；不支持 `prefers-reduced-motion` 时不播放动效。不做每次保存撒花、不做循环动画、不加音效。

### F0 账号与身份认证（P0，v1.1.1）

**用户故事**
> 作为用户，我想只用用户名和密码注册、登录，让账本只属于我；换设备时，登录后能通过备份继续使用自己的账本。

**范围与前提**
- 注册只收 **用户名、密码、确认密码**；不收集邮箱、手机号，不发送验证码，不接第三方登录。
- v1.1.1 的账号只负责**身份认证与本地账本归属**；认证服务不存储账目、分类、备注、金额。
- 登录不等于云同步：换设备或清缓存后，仅登录不会带回账目，必须导入备份。
- 除登录 / 注册 / 找回密码外，所有页面均需有效会话。
- 认证页不得加载第三方统计、广告或社交 SDK；分析脚本如存在，不得读取表单内容。

#### F0.1 注册

**字段与规则**

| 字段 | 规则 |
| --- | --- |
| 用户名 | 2–20 个字符；支持中文、英文字母、数字、下划线；不允许空格、标点、emoji；首尾空格自动去除；做 Unicode NFKC 归一化；**不区分大小写判重**，展示保留用户输入的大小写 |
| 密码 | 8–64 个字符；至少包含 1 个字母和 1 个数字；允许特殊字符与空格；不自动 trim；不显示明文（可切换显示） |
| 确认密码 | 必须与密码一致；仅用于前端校验，不上传、不存储 |

> 「确认密码」只是同一凭据的二次输入，不增加新的个人信息；恢复码在注册成功后自动生成，不是注册必填字段。注册仍只收集用户名与密码。

**用户名限制**
- 保留名不可注册：`admin`、`administrator`、`support`、`official`、`qingji`、`轻记`、`客服`、`官方` 等（服务端维护保留表）。
- 用户名不是公开主页，不提供搜索用户、@提及、用户目录，降低冒用与骚扰风险。
- 用户名修改：v1.1.1 **不支持修改**；注册页需提示「用户名注册后不可更改」。

**交互流程**
1. 登录页点击「注册」→ `/register`。
2. 输入用户名、密码、确认密码；实时做本地格式校验，不在输入过程中请求服务端。
3. 勾选「我已阅读并同意隐私说明」（不预勾选）；未勾选时注册按钮不可用。
4. 点击「注册」→ 服务端校验用户名唯一性与密码强度。
5. 成功 → 建立会话并自动登录 → 检查本机是否有未绑定的 v1.0 账本：
   - 有：展示「把本机 X 笔账目绑定到 @username？」→ 确认后迁移；
   - 无：初始化该账号的空账本与默认分类。
6. 进入明细页，展示一次性提示「数据仍在本机，记得定期备份」。
7. 若启用恢复码（P1），注册成功后展示一次恢复码，要求用户确认已保存；不保存也可继续使用，但会明确提示「忘记密码将无法自助找回」。

**错误文案**
| 情况 | 文案 |
| --- | --- |
| 用户名为空 / 格式错误 | 「用户名需为 2–20 个字符，支持中文、字母、数字和下划线」 |
| 用户名已存在 | 「这个用户名已经被使用了，换一个试试」 |
| 密码过短 | 「密码至少 8 位」 |
| 缺少字母或数字 | 「密码需要同时包含字母和数字」 |
| 两次密码不一致 | 「两次输入的密码不一致」 |
| 网络失败 | 「网络不太稳定，请稍后再试」 |
| 请求超时 / 响应丢失 | 「如果刚刚已经注册成功，请直接去登录」 |

**验收标准**
- [ ] 注册全过程不出现邮箱、手机号、验证码、第三方登录入口。
- [ ] 用户名大小写不同但归一化相同（如 `Amy` / `amy`）时判重。
- [ ] 密码错误提示只说明规则，不回显密码内容。
- [ ] 注册成功后自动登录，无需二次输入。
- [ ] 数据库中只能看到密码哈希，不能看到明文密码。
- [ ] 注册请求超时后重试不会创建重复账号；提示用户可尝试登录。

#### F0.2 登录

**字段**
- 用户名、密码；提供「显示 / 隐藏密码」按钮，按钮需有可访问名称。
- 输入框使用 `autocomplete="username"` 与 `autocomplete="current-password"`，兼容密码管理器。
- 不提供公开用户目录；不在 localStorage 保存密码或会话凭证。

**规则**
- 登录成功后签发 30 天会话（HttpOnly Cookie），默认自动登录，不提供「7 天 / 30 天」复杂选项。
- 用户名按 F0.1 的规则做 NFKC、去首尾空格、大小写不敏感匹配；密码区分大小写。
- 用户名或密码错误统一提示「用户名或密码不正确」，不区分「用户不存在」与「密码错误」。
- 服务端对未知用户执行一次假哈希校验，降低通过响应时间枚举用户名的可能。
- 若恢复码功能（P1）未上线，「忘记密码」入口展示说明页，明确告知无法自助找回，不出现无法使用的空表单。
- 登录限流：同一用户名 + IP 组合 15 分钟内最多 5 次失败；超过后返回 429，提示「尝试次数过多，请 15 分钟后再试」。
- 登录成功后若该账号在当前浏览器没有账本：创建空账本与默认分类，并展示「这台设备还没有 @username 的账本，可从备份导入」提示。
- 若浏览器存在未绑定的 v1.0 账本：顶部提示「本机还有一份未绑定账号的旧账本」；允许先导出备份，登录不会删除旧账本。
- 登录失败不泄露账号是否存在；日志中不记录密码、Cookie、恢复码。

**登录后行为**
- 读取该账号对应的 IndexedDB（`qingji-u-<userId>`）；没有则创建默认分类与设置。
- 回到 `next` 参数指定的页面；没有 `next` 则进入明细页。
- 多标签页登录 / 退出：通过 `BroadcastChannel` 或 `storage` 事件同步，其他标签页在下次写入或路由切换时重新校验会话。

**边界情况**
| 情况 | 处理 |
| --- | --- |
| 已登录用户访问 `/login` | 直接跳转明细页 |
| 会话过期时正在记账 | 允许完成当前本地保存；保存成功后提示重新登录，账目留在本机 |
| 离线且从未登录过 | 只显示登录页，提示需要网络；不能注册 / 登录 |
| 离线但此前登录过且本机有该账号账本 | 允许进入「离线模式」，仅使用本地账本；顶部显示离线状态；联网后重新校验会话 |
| Cookie 被浏览器禁用 | 登录失败并提示检查隐私设置；不提供 token 放 localStorage 的降级方案 |
| 连续快速点击登录 | 按钮进入 loading 并防重复提交 |
| 密码管理器自动填充 | 正常识别并允许提交 |

**验收标准**
- [ ] 用户名不存在与密码错误返回相同文案与相同 HTTP 状态。
- [ ] 15 分钟内第 6 次失败开始返回 429，且提示可理解。
- [ ] 登录成功后刷新页面仍保持登录（30 天内）。
- [ ] 未登录直接访问 `#/stats` 会跳转登录页，登录后回到统计页。
- [ ] 登录新设备时不会显示其他账号的账目。
- [ ] 密码不出现在 URL、前端日志、分析事件或错误上报中。

#### F0.3 会话与自动登录（P0）

- **Cookie**：`HttpOnly`、`Secure`、`SameSite=Lax`、`Path=/`；不得通过 JavaScript 读取。
- **服务端会话**：会话 ID 随机生成，服务端保存哈希；登录成功时轮换会话 ID，防止会话固定攻击。
- **有效期**：默认 30 天；可在服务端吊销；修改密码后吊销其他会话。
- **启动校验**：应用启动先请求 `GET /api/auth/me`；校验期间不渲染账本内容。
- **失效处理**：返回 401 时清除前端登录态，跳转 `/login?next=...`；本地账本不清空。
- **离线模式**：仅当「本机曾成功登录该账号 + 本地存在该账号账本 + 上次校验未超过 30 天」时允许离线进入；联网后立即重新校验。离线期间不提供注册、登录、找回密码。
- **认证服务故障**：网络可用但认证 API 返回 5xx / 超时，若本机满足上述离线条件，可进入「受限离线模式」，顶部提示「认证服务暂时不可用，正在使用本机账本」；不展示其他账号，不提供改密/退出全部设备；恢复后重新校验。
- **防 CSRF**：所有写操作校验 `Origin` / `Referer` 并携带 CSRF token；认证接口同样校验。
- **多设备**：v1.1.1 允许多设备同时登录，但数据不互通；「退出所有设备」随修改密码提供（P1）。

**验收标准**
- [ ] 30 天内正常刷新不需要重新登录；超过 30 天回到登录页。
- [ ] 会话失效时本地账本不被删除或清空。
- [ ] 断网但此前已登录且本机有账本时，可进入离线模式；登录/注册/找回按钮不可用并有说明。
- [ ] 认证服务 5xx 时，不会误跳转其他账号或清空本地数据。
- [ ] 修改密码后，其他设备的下一次请求返回 401。

#### F0.4 退出登录（P0）

- 入口：「我的 → 账号与安全 → 退出登录」。
- 二次确认：「退出后，本机账本仍会保留。重新登录即可继续使用。」
- 行为：调用 `POST /api/auth/logout` 吊销当前会话 → 清除 Cookie → 跳转登录页。
- **不删除**本地账本；如需彻底清除，另走「数据与备份 → 清除数据」。
- 共用设备提示：退出只能阻止他人进入你的账号，不能抹掉浏览器磁盘上的账本；敏感场景建议清除数据。
- 离线时不制造「已安全退出」的假象：提示需要联网吊销服务端会话；如共用设备需立即保护，使用「清除本机数据」并尽快联网退出。
- 验收：退出后返回键无法回到账本内容；重新登录后账本完整恢复；离线退出有明确提示。

#### F0.5 修改密码（P1，建议 v1.1.1）

- 入口：「我的 → 账号与安全 → 修改密码」。
- 字段：当前密码、新密码、确认新密码。
- 校验：当前密码正确；新密码符合 F0.1 规则；新密码不得与当前密码相同。
- 成功后：保留当前会话，吊销其他设备会话；展示「其他设备需要重新登录」。
- 失败：统一提示「当前密码不正确」，不泄漏更多信息；限流。
- 不提供密码提示问题；不通过客服人工改密（无恢复码时除外）。
- 验收：修改后旧密码无法登录；当前会话仍可用；其他会话失效。

#### F0.6 恢复码与找回密码（P1，建议与 v1.1.1 同期）

> 因为没有邮箱和手机号，恢复码是用户唯一可自助找回账号的凭证。

**恢复码生成**
- 注册成功时自动生成 16 位恢复码（如 `7K2M-9QXA-4T8P-W3NC`），只在注册成功页展示一次。
- 提供「复制」与「下载为文本」；默认建议勾选「我已保存」；跳过时需二次确认「忘记密码将无法自助找回」。
- 服务端只保存恢复码哈希；不保存明文。
- 用户可在「账号与安全」中用当前密码重新生成恢复码，旧码立即失效。

**找回流程**
1. 登录页 →「忘记密码」→ `/recover`。
2. 输入用户名 + 恢复码 + 新密码 + 确认新密码。
3. 校验通过 → 更新密码哈希、吊销全部会话、销毁旧恢复码 → 提示「密码已重置，请用新密码登录」。
4. 可选：重置成功后生成新恢复码并展示一次。

**限制**
- 没有保存恢复码的用户，**无法自助找回**；页面必须明确说明，不承诺客服一定可恢复。
- 找回接口同样限流，错误统一提示「用户名或恢复码不正确」。
- 恢复码不得出现在 URL、日志、分析事件中。

**验收**
- [ ] 恢复码只在生成时显示一次，之后不可再次查看明文。
- [ ] 使用恢复码重置后，旧密码和所有旧会话失效。
- [ ] 错误恢复码不会泄露用户名是否存在。
- [ ] 未启用恢复码时，注册页和登录页明确告知「忘记密码无法找回」。

#### F0.7 账号数据隔离与旧账本迁移（P0）

**本地数据库隔离**
- v1.0 的 `qingji` 数据库视为「未绑定账本」。
- 每个账号使用独立数据库：`qingji-u-<userId>`；包含原有 `transactions`、`categories`、`settings`、`meta` 四个 Store。
- 账号切换、退出登录只切换打开的数据库，不删除数据。
- 同一浏览器可保留多个账号的本地账本；任一时刻只打开当前账号的数据库。
- 认证服务端**不保存账目**；账号删除时默认只删除服务端身份，本地账本由用户选择是否一并清除。

**v1.0 → v1.1.1 迁移流程**
1. 检测 `qingji` 中存在账目。
2. 用户注册成功后，提示「本机有 X 笔账目，是否绑定到 @username？」。
3. 用户确认 → 自动导出一份旧账本 JSON 备份 → 在 IndexedDB 事务中复制到 `qingji-u-<userId>` → 校验条数、分类数一致。
4. 迁移成功 → 标记旧库为「已迁移」；**至少保留 30 天**，期间在设置中提供「删除旧账本」按钮；不自动删除。
5. 迁移失败 → 不标记、不删除旧库；恢复到迁移前状态，提示重试或导出备份。
6. 用户拒绝绑定 → 旧库保留；当前账号进入空账本；「我的」中持续显示「本机有未绑定账本」。

**登录已有账号时**
- 若当前浏览器存在未绑定旧账本，登录页与登录后均提示其存在；不得自动合并、覆盖或删除。
- 提供「先导出旧账本」；用户可选择把旧账本导入当前账号（按备份导入流程，明确提示会覆盖当前账本）。

**备份与恢复**
- 备份 JSON 不包含密码、会话、恢复码。
- 备份可跨账号导入；导入前提示「这些账目将归属于当前账号 @username」。
- 新设备登录后没有账本时，创建空账本与默认分类，但首页必须显著展示「从备份导入」入口；不得自动生成账目或合并其他账号数据。
- v1.1.1 不提供自动多设备同步。

**验收**
- [ ] 账号 A 与账号 B 在同一浏览器登录后，彼此看不到对方的账目。
- [ ] 退出登录后本机账本仍在，重新登录可恢复。
- [ ] 迁移前后账目条数、分类数一致；迁移中断不丢失旧数据。
- [ ] 迁移前自动生成一份可下载的旧账本备份。
- [ ] 登录新设备时不会自动创建空账本并覆盖已有导入入口。
- [ ] 导入备份不会把数据写到其他账号数据库。

#### F0.8 账号与安全页（P0/P1）

「我的 → 账号与安全」展示：

| 区块 | 内容 | 优先级 |
| --- | --- | --- |
| 账号信息 | 用户名、注册时间；用户名不可修改 | P0 |
| 密码 | 修改密码 | P1 |
| 恢复码 | 生成 / 重新生成 / 保存提示（不显示明文） | P1 |
| 会话 | 退出登录；修改密码时提示其他设备下线 | P0/P1 |

**注销账号规则（P1）**
- 必须验证当前密码，并输入用户名二次确认。
- 提示「注销后账号无法恢复；本机账本可选择保留或一并删除」。

- 若用户仅想换设备或换浏览器，不应注销账号；页面提供「导出备份」入口。

#### F0.9 安全与错误处理要求

- **密码存储**：Argon2id（优先）或 bcrypt（cost ≥ 12）；每个密码独立盐；绝不加密可逆存储，绝不明文。
- **传输**：全站 HTTPS + HSTS；认证接口仅接受 HTTPS。
- **接口限流**：注册、登录、找回密码按 IP + 用户名限流；返回 429 与 `Retry-After`。
- **账户枚举**：登录与找回统一错误文案；注册的用户名占用提示不可避免，但需限流，且不提供用户搜索。
- **注入与 XSS**：所有输入服务端校验；前端输出转义；认证页使用严格 CSP，仅允许 self / nonce，不加载第三方脚本。
- **会话安全**：HttpOnly + Secure + SameSite=Lax；登录轮换会话；修改密码吊销其他会话；服务端可强制下线。
- **日志**：不记录密码、恢复码、Cookie、Authorization；错误日志只记录请求 ID、状态码、脱敏用户名。
- **错误上报**：不把表单值或响应体中的敏感字段发送到第三方。
- **依赖安全**：认证依赖锁定版本，上线前做依赖漏洞扫描。
- **测试**：至少覆盖撞库、暴力破解、会话固定、CSRF、XSS、SQL 注入、用户名枚举、越权读取他人账本。

**统一错误码（示例）**

| HTTP | 场景 | 前端文案 |
| --- | --- | --- |
| 400 | 参数格式错误 | 按字段提示具体规则 |
| 401 | 未登录 / 会话失效 | 请重新登录 |
| 403 | CSRF 校验失败 | 页面已过期，请刷新后重试 |
| 409 | 用户名已存在 | 这个用户名已经被使用了 |
| 429 | 请求过于频繁 | 尝试次数过多，请稍后再试 |
| 500 | 服务端异常 | 服务暂时不可用，请稍后再试 |

### F1 快速记一笔（P0，v1.0）

**用户故事**
> 作为用户，我在付完钱后打开网页，希望不假思索地记下这笔消费，不需要填写多余信息。

**前提**
- 必须先登录；未登录访问 `/record` 会跳转 `/login?next=/record`。

**入口**
- 手机：明细页右下角悬浮「+」
- 桌面：右上角「记一笔」按钮
- 桌面键盘快捷键：`N`（焦点不在输入框时）
- 已安装 PWA 的应用快捷方式（P2）
- 记账页地址 `/record` 可直接访问/收藏

**页面结构**
1. 顶部：关闭（✕）、标题「记一笔」
2. 类型切换：支出 / 收入（默认支出，记住上次选择）
3. 金额区：大字号输入框，使用浏览器原生数字键盘（`inputmode="decimal"`）
4. 分类区：胶囊按钮列表，按「最近使用 + 高频」排序，默认预选
5. 附加字段：日期（默认今天；快捷：今天 / 昨天 / 自定义）、备注（选填，≤200 字）
6. 底部：主按钮「保存」；手机端吸底，避免被键盘遮挡
7. 「保存并再记一笔」开关（记忆上次状态，默认关）

**交互规则**
- 打开页面后自动聚焦金额输入框。注意：部分手机浏览器要求必须在用户点击的事件栈内聚焦才会弹出键盘；若未弹出，页面需有明确的「点击输入金额」提示，不能出现「看起来卡住」的状态。
- 金额支持 `0.01`–`9,999,999.99`，最多两位小数；输入框内不出现千分位与负号，展示时格式化。
- 键盘：手机端使用系统数字键盘（不实现自定义键盘，避免与浏览器键盘冲突）；桌面端支持数字键、回车保存；`Esc` 关闭。
- 分类预选逻辑（按优先级）：
  1. 备注命中本地关键词规则（如「地铁」→ 交通、「咖啡」→ 餐饮/咖啡茶饮）；
  2. 否则按当前时间段推荐（如 11:30–13:30 → 午餐）；
  3. 否则选中最近一次使用的分类。
- 分类推荐为「默认选中」，用户不改也可保存；点击其他分类即覆盖。
- 保存成功后：关闭记账页 → 返回明细并定位到今天 → 顶部 toast「已记 ¥28.00 · 🍜 午餐」，保留 5 秒「撤销」。
- 「保存并再记一笔」开启时：清空金额与备注，保留分类/日期，页面不关闭。
- 浏览器返回键（`popstate`）关闭记账页；若已有输入，需二次确认「放弃这笔记录？」。
- 输入过程中将草稿写入 `sessionStorage`（含金额、分类、备注、日期），刷新或误关闭后恢复；保存或主动放弃后清除草稿。
- 已打开的页面在断网时仍可保存到本地。

**边界情况**
| 情况 | 处理 |
| --- | --- |
| 金额为 0 或为空 | 保存按钮置灰，点击给出轻提示「请输入金额」 |
| 金额超过上限 | 阻止输入并提示上限 |
| 连续点击保存 / 回车连按 | 幂等，只生成一笔 |
| 保存瞬间关闭页面 | 本地事务已提交，下次打开可见；若未提交则草稿可恢复 |
| 分类被删除后再次记账 | 自动回退到「其他」或最近有效分类 |
| 跨天（23:59 操作已过 0 点） | 以用户选择的日期为准，默认仍为打开记账页时所在日期 |
| 手机键盘弹起遮挡保存按钮 | 使用 `visualViewport` / `dvh` 适配，保存按钮始终可见 |
| iOS 输入框聚焦自动放大 | 金额与备注输入框字号 ≥ 16px，禁止页面缩放 |
| 微信内置浏览器返回手势 | 不拦截默认返回；未保存时通过页面内确认层处理 |

**验收标准**
- [ ] 新用户首次记一笔 ≤ 15 秒（含选择分类）。
- [ ] 熟练用户从点击「+」到保存 ≤ 6 秒，点击次数 ≤ 3 次（金额 → 分类 → 保存）。
- [ ] 在 320px 宽度屏幕上完整可用，无横向滚动、无按钮遮挡。
- [ ] 已在页面内时断网，仍可完成记账并看到数据。
- [ ] 保存后 100ms 内可见反馈，无白屏、无整页刷新。
- [ ] 浏览器返回键关闭记账页，不退出站点。
- [ ] 刷新页面后未保存的草稿可恢复。

### F2 账目管理与撤销（P0，v1.0）

**用户故事**
> 作为用户，我记错金额或分类时，希望能快速修改；误删时能找回。

**列表**
- 按日期倒序分组，每组显示「日期 + 当日支出/收入小计」。
- 每条展示：分类图标、分类名（或备注优先）、金额；支出为深色，收入使用辅助色，需通过色盲适配（不单靠颜色区分）。
- 顶部概览：本月支出、收入、结余。
- 手机端下拉刷新禁用（无后端），使用「回到顶部」按钮替代。
- 桌面端支持鼠标悬停显示编辑/删除图标；手机端支持左滑，同时提供始终可见的「更多」菜单，避免手势不可发现。
- 空状态：轻量插画 + 「今天还没有记账」+「记一笔」按钮。
- 列表按当前月份加载；单月数据量较大时分页或虚拟滚动（≥ 500 条时启用）。

**编辑**
- 点击账目打开编辑页（与记账页同一表单），预填全部字段。
- 支持修改金额、分类、日期、备注；保存后列表与统计即时更新，无需刷新。

**删除**
- 手机：左滑或「更多」→ 删除；桌面：悬停图标或右键菜单。
- 删除后 toast「已删除 · 撤销」，5 秒内可恢复；超时后进入回收站（保留 30 天，P1）。
- 删除为软删除（保留 `deleted_at`），为后续同步与恢复留出空间。

**搜索与筛选（P1，v1.1）**
- 搜索：备注、分类名、金额（精确）、日期范围。
- 筛选：类型、分类、金额区间。
- 结果列表复用账目卡片，显示命中总数；手机端搜索入口位于明细页顶部。

**验收标准**
- [ ] 编辑保存后，首页概览与统计页数据同步刷新，无需手动刷新。
- [ ] 删除后 5 秒内撤销成功，数据与统计恢复一致。
- [ ] 1000 条账目下滚动流畅（手机中端机 60fps，桌面无卡顿）。
- [ ] 桌面端所有操作均可用键盘完成（Tab 聚焦、Enter 确认）。
- [ ] 手机端删除操作既支持左滑，也有可见的菜单入口。

### F4 统计与概览（P0，v1.0）

**明细页概览**
- 本月支出（大字）、较上月环比（百分比 + 箭头，颜色克制）。
- 本月收入、结余。
- 预算进度（v1.1 设置后显示）。

**统计页**
1. **时间切换**：月 / 年；左右按钮切换上一期/下一期；手机端可选横向滑动，但不得与页面滚动冲突。
2. **类型切换**：支出 / 收入。
3. **核心数字**：总额、日均、笔数、最大单笔。
4. **分类占比**：环形图 + 排行列表（Top 5 + 其他），展示金额、占比、环比。
5. **趋势**：近 6 个月（年视图为近 12 个月）柱状图；点击柱子切换月份。
6. **下钻**：点击分类 → 该分类账目列表（可继续编辑）。
7. **状态同步**：当前月份、类型写入 URL 查询参数，刷新或分享链接后保持同一视图。
8. **空状态**：当期无数据时展示引导，不展示空白图表。

**规则**
- 统计口径按账目 `occurred_at` 的本地日期归属。
- 金额展示保留两位小数；占比保留整数百分比，合计可能因四舍五入不等于 100%，需做尾差处理或 UI 说明。
- 环比：与上一自然月整月对比；当月未结束时在 UI 标注「较上月」口径。

- 手机端图表使用点击/长按查看数值；桌面端支持悬停提示。

**验收标准**
- [ ] 任意新增/编辑/删除账目后，统计数字与列表在 200ms 内一致更新。
- [ ] 分类占比之和为 100%（含「其他」兜底）。
- [ ] 跨年切换（12 月 → 次年 1 月）正常。
- [ ] 统计页刷新后仍停留在原月份与类型。
- [ ] 320px 宽度下图表与排行不溢出、不被裁切。

### F5 数据备份、导出与恢复（P0，v1.0；v1.1.1 沿用）

> Web 形态下数据只存在当前浏览器，这是 v1 最大的产品风险。此功能必须与核心记账同时上线，不能延期。v1.1.1 引入账号后，**备份仍然是换设备与防丢失的唯一手段**，且备份只在当前登录账号的账本空间内生效。

**能力**
1. **完整备份（JSON）**
   - 导出当前登录账号的全部账目、分类、设置与版本信息，生成 `.json` 文件。
   - 文件内含 `format`、`version`、`exportedAt`、数据摘要（账目数、时间范围）。
   - **不包含**密码、会话 Cookie、恢复码、账号凭证。
   - 支持下载到手机「文件」/电脑默认下载目录。
   - 微信内置浏览器等下载受限环境：提供「复制备份内容到剪贴板」的降级方案，并提示可在系统浏览器中完成导出。
2. **CSV 导出**
   - 字段：日期、类型、一级分类、二级分类、金额、备注。
   - UTF-8 带 BOM，确保 Excel 打开中文不乱码。
   - 支持按时间范围导出。
3. **导入恢复（JSON）**
   - 导入前校验文件格式与版本，展示预览：备份时间、账目条数、分类数、数据时间范围。
   - 明确提示「这些账目将归属于当前账号 @username」，不得写入其他账号数据库。
   - 支持两种模式（v1.0 至少实现「覆盖恢复」）：
     - **覆盖恢复**：清空当前账号数据后恢复（默认，需二次确认）；
     - **合并导入**：按 ID 去重合并（P1）。
   - 恢复前自动将当前账号数据导出一份临时备份（安全兜底）。
   - 版本不兼容时给出明确提示，不执行部分写入。
4. **备份提醒**
   - 当「距上次备份 > 14 天且有新增账目」时，在「我的」页与明细页顶部展示一条可关闭的温和提示。
   - 不使用弹窗打断记账；提醒状态按账号存储。
5. **存储状态**
   - 展示当前数据量（条数、估算占用）与浏览器存储状态。
   - 在支持 `navigator.storage.persist()` 的浏览器中主动申请持久化存储，并展示结果。
   - 明确提示：清除浏览器数据 / 无痕模式 / 部分浏览器的自动清理可能导致数据丢失。
6. **清除数据**
   - 仅清除当前账号的本地账本；不清除登录账号本身（注销账号见 F0.8）。
   - 二次确认 + 输入确认词；清空后不可撤销。
   - 清除前提示先导出备份。
7. **未绑定旧账本**
   - v1.0 的旧账本不属于任何账号；登录后若检测到，提供「导出」「绑定到当前账号」「保留」三种处理，详见 F0.7。

**首次登录说明**
- 首次登录时展示一条可关闭的说明：「账目保存在当前浏览器，请定期备份。登录不会把账目同步到其他设备；添加到主屏幕可作快捷入口，但 iOS 上可能使用独立存储，安装前请先导出备份。」
- 不阻塞记账；可再次在「我的 → 数据与备份」查看。

**验收标准**
- [ ] 导出 JSON 后，在另一浏览器/设备登录同一账号并导入，账目、分类、设置完整还原，条数一致。
- [ ] 备份文件中不出现密码、会话、恢复码。
- [ ] 账号 A 导入备份不会写入账号 B 的账本。
- [ ] CSV 用 Excel 与 Numbers 打开，中文、金额、日期均正确。
- [ ] 导入非法/损坏文件时不破坏现有数据，并给出可理解的错误提示。
- [ ] 清除数据需至少两步确认，且不可通过撤销恢复。
- [ ] 备份提醒不打断记账流程，可关闭且不会每次刷新都出现。
- [ ] 恢复失败时，当前数据仍可通过自动临时备份找回。

### F6 响应式布局与手机浏览器适配（P0，v1.0）

> 这是 Web 版的「生死线」：手机浏览器上的体验必须接近原生，而不是把桌面页面缩小。

**断点与布局**

| 宽度 | 布局 |
| --- | --- |
| < 640px（手机） | 单列；底部 3 Tab；悬浮「+」；记账页全屏；表单吸底保存 |
| 640–1023px（大屏手机/平板） | 单列加宽，内容最大 720px；顶部导航；底部 Tab 保留 |
| ≥ 1024px（桌面） | 内容最大 1080px；顶部导航；明细页两栏（列表 + 本月概览）；记账为居中弹窗 |

**手机端必须处理**
- 安全区：`env(safe-area-inset-bottom)`，避免底部导航被 iPhone Home 指示条遮挡。
- 视口高度：使用 `100dvh` + 回退，避免地址栏收起/展开导致布局跳动。
- 触控目标 ≥ 44×44px；间距足够，避免误触。
- 不依赖 hover：所有悬停操作必须有触摸等价入口。
- 输入框字号 ≥ 16px，避免 iOS 聚焦自动放大。
- 虚拟键盘：使用 `visualViewport` 监听，保存按钮与当前输入不被遮挡。
- 禁用双击缩放与横向滚动；保留用户双指缩放（不设置 `user-scalable=no`）。
- 滚动性能：长列表使用 `content-visibility` 或虚拟滚动。
- 页面切换与弹窗：使用 History API，返回键行为符合浏览器预期。

**桌面端增强**
- 键盘快捷键：`N` 新建、`Esc` 关闭、`Enter` 保存（输入框内）、`/` 聚焦搜索（v1.1）。
- 悬停显示操作按钮；右键菜单（可选）。
- 两栏布局充分利用宽度，不把移动端页面简单拉伸。

**浏览器兼容**
- iOS Safari 15+、Android Chrome 90+、微信内置浏览器（iOS WKWebView / Android X5）。
- 桌面：Chrome / Edge / Safari / Firefox 最近两个大版本。
- 不支持 IE；对不支持的浏览器展示升级提示，不白屏。
- 微信内置浏览器中，若功能受限（如 PWA 安装、部分存储能力、认证 Cookie 被拦截），优雅降级并提示「在系统浏览器中打开」。
- 认证页需验证 Cookie 可写入；若浏览器禁用 Cookie，登录不可用并给出明确提示，不降级为 localStorage 会话。

**验收标准**
- [ ] 在 iPhone Safari、Android Chrome、微信内置浏览器中完成「注册 → 登录 → 记账 → 编辑 → 查看统计」全流程。
- [ ] 认证页在 320px 宽度下无横向滚动，键盘弹起时输入框与提交按钮均可见。
- [ ] 微信内置浏览器无法下载文件时，导出具备降级路径（复制备份内容 / 引导在系统浏览器打开），且有明确提示。
- [ ] 320px / 375px / 390px / 768px / 1440px 五种宽度下无横向滚动、无内容遮挡。
- [ ] 手机键盘弹起时，金额与保存按钮均可见。
- [ ] 浏览器返回键依次关闭弹窗/返回上一页，不直接退出。
- [ ] 横屏下核心流程可用。
- [ ] 200% 浏览器缩放/大字号下文字不重叠、按钮可点击。
- [ ] 不支持的浏览器有明确提示，不出现白屏。

### F7 PWA 与离线能力（P1，v1.1）

- 提供 `manifest.webmanifest`：名称、图标、主题色、启动方式、`display: standalone`。
- 手机端引导「添加到主屏幕」（Android 使用安装提示；iOS 展示 Safari 分享 → 添加到主屏幕的图文指引），不反复打扰。
- Service Worker 缓存应用外壳与静态资源，二次打开可离线加载；缓存版本化，更新时提示「有新版本，点击刷新」。
- 离线状态条：显示「当前离线，数据将保存在本机」；恢复网络后自动消失。
- 限制说明：微信内置浏览器可能不支持 Service Worker 或安装，需降级为普通网页。
- **iOS 存储隔离提醒**：添加到主屏幕的 Web App 可能与 Safari 使用彼此隔离的存储。安装引导不得将「添加到主屏幕」宣传为保数据手段；安装前提示先导出备份，安装后若首次打开为空，提供「导入备份」入口。
- 不在 v1.0 强依赖 PWA；普通浏览器访问必须完整可用。

**验收标准**
- [ ] 安装到主屏幕后，断网可打开并完成记账、查看统计。
- [ ] 新版本发布后，用户可看到更新提示并刷新到新版本，不出现缓存死锁。
- [ ] 卸载/清除站点数据后，重新访问可正常使用（数据需提前备份）。
- [ ] iOS 上安装前后若存储不互通，用户能看到明确的备份/导入指引，不会误以为数据丢失。

### F9 账户与转账（P1，v1.1）

- 默认账户：现金、微信、支付宝、银行卡、信用卡、其他（可增删改）。
- 记账时增加「账户」字段（默认上次使用）；未开启账户功能时该字段隐藏，保持极简。
- 账户余额可选开启；转账生成 `transfer` 类型记录，不计入收支统计。
- 删除账户前必须迁移其账目。
- 验收：转账后统计不受影响；余额计算正确；关闭账户功能后历史数据不丢失。

---

### F10 搜索与筛选（P1，v1.1）

- 搜索备注、分类名、金额、日期范围。
- 筛选类型、分类、金额区间。
- 手机端搜索为全屏页；桌面端为顶部搜索框 + 下拉结果。
- 验收：结果准确、可分页、可回到原列表位置。

### F11 隐私与安全（P1，v1.1；账号安全见 F0.9）

- **隐私模式**：一键模糊明细与统计中的金额，适合地铁/办公室场景；刷新后保持设置。
- **清除数据**：随时可清除本地数据（见 F5）。
- **传输安全**：全站 HTTPS；静态资源自托管或可信 CDN。
- **前端安全**：严格 CSP；无第三方广告/统计脚本读取页面内容；所有用户输入转义，防止 XSS。
- **账号相关**：会话使用 HttpOnly Cookie；退出登录后账本不可见；共用设备需手动清除数据才能抹除磁盘上的账本。详见 F0.9。
- **分析数据**：仅上报匿名事件，不含金额、备注、分类名；提供关闭开关。
- **可选应用锁**（P2）：4 位 PIN，仅作为界面锁，不承诺数据库加密；文案不得暗示「加密存储」。
- **说明**：v1.1.1 本地数据未做端到端加密，账号密码不等于本地数据库加密；设备被他人直接访问时仍存在暴露风险，需在隐私说明中如实告知。

### F12 周期记账（P2，v1.2）

- 支持每周/每月/每年规则，如「每月 1 日房租 ¥3,500」。
- Web 无后台任务：用户打开页面时检查并补生成缺失账目（最多补 12 期）。
- 生成后应用内提示，可编辑本期金额；规则暂停/删除不影响已生成账目。
- 幂等键：规则 ID + 周期。

---

### F13 智能洞察（P2，v1.2）

- 基于本地规则生成月度总结，如「本月外卖 12 次，比上月多 4 次」「餐饮占支出 38%，为最大类目」。
- 全部在本地计算，不上传账目内容。
- 提供关闭入口；文案保持中性、不评判。

---

### F14 云同步（P2，v1.2+，依赖 v1.1.1 账号）

- v1.1.1 **不做云同步**；账号与账本是两件事：登录只证明身份，账目仍在本机。
- 云同步需要把账目、分类、设置上传到服务端；必须单独设计端到端加密、密钥管理与冲突策略，不能复用 v1.1.1 的认证服务端存储。
- 建议端到端加密：密钥由用户密码派生，服务端只存密文；用户忘记密码且无恢复码时，云端数据不可恢复。
- 冲突策略：最后写入优先 + 冲突日志；同步前本地快照；首次同步需明确「本机账本 / 云端账本」合并方式。
- 上线前需完成隐私合规评估、数据安全设计与用户明确授权。
- 该功能会显著增加研发与运维成本，需在 v1.1.1 数据验证后决策。

---

### F15 多币种与自定义账期（P2）

- 多币种：手动维护汇率，统计可按本币折算；不接入实时汇率。
- 自定义账期：支持按发薪日设置起始日，与预算、统计联动。

## 8. 数据模型

> 金额统一使用**整数分（cents）**存储，避免浮点误差；时间统一存 UTC 毫秒，展示时按浏览器本地时区转换。

### 8.1 本地存储

- 使用 **IndexedDB**，不使用 `localStorage` 存业务数据；每个账号使用独立数据库：
  - `qingji-u-<userId>`：当前登录账号的账本；
  - `qingji`：v1.0 遗留的「未绑定账本」，只用于一次性迁移。
- 每个账号数据库包含以下 Object Store：
  - `transactions`：主键 `id`；索引 `occurredAt`、`categoryId`、`deletedAt`
  - `categories`：主键 `id`
  - `settings`：键值对
  - `meta`：`schemaVersion`、`createdAt`、`deviceId`、`lastBackupAt`、`userId`
- 所有写操作在单个 IDB transaction 中完成；写入失败需回滚并提示。
- 每个账号首次打开时写入默认分类与默认设置。
- 前端只在内存/短期存储中保存 `userId`、`username`、`lastVerifiedAt` 等非敏感登录态展示信息；**会话凭证只放 HttpOnly Cookie**，不写 localStorage。
- 认证服务端不保存账目、分类、备注、金额；账本数据与账号密码在物理上分离。

### 8.2 表结构

```text
transaction（账目）
  id              TEXT PK       UUID v4
  type            TEXT          expense | income
  amount_cents    INTEGER       1 – 999,999,999
  currency        TEXT          固定 CNY（v1）
  category_id     TEXT FK
  note            TEXT          可空，≤200 字
  occurred_at     INTEGER       账目发生时间（UTC ms）
  created_at      INTEGER
  updated_at      INTEGER
  deleted_at      INTEGER       软删除（可空）
  source          TEXT          manual | import

category（分类）
  id              TEXT PK
  name            TEXT
  parent_id       TEXT FK       可空，最多两级
  type            TEXT          expense | income
  icon            TEXT          SVG 标识
  color           TEXT          十六进制
  sort            INTEGER
  is_system       BOOLEAN       系统分类不可删除
  hidden          BOOLEAN

settings（设置，key-value）
  key             TEXT PK       theme | lastCategoryId | privacyMode |
                                lastBackupAt | backupReminderEnabled |
                                lastType | onboarded
  value           TEXT / JSON

meta（元信息）
  key             TEXT PK
  value           TEXT / JSON
```

### 8.3 备份文件格式

```json
{
  "format": "qingji-backup",
  "version": 1,
  "exportedAt": 1790000000000,
  "summary": {
    "transactionCount": 386,
    "categoryCount": 19,
    "range": { "from": 1780000000000, "to": 1790000000000 }
  },
  "data": {
    "transactions": [],
    "categories": [],
    "settings": {},
    "meta": {}
  }
}
```

**导入规则**
- 校验 `format` 与 `version`；未知版本拒绝导入并提示。
- 先完整解析与校验，再执行写入；任何一步失败都不得破坏现有数据。
- 覆盖模式：写入前自动导出当前数据为临时备份（保留在内存，直到用户离开页面）。
- 导入后刷新统计缓存与界面。
- 备份**不包含**账号凭证、密码、Cookie、恢复码；导入后数据归属当前登录账号，不跨账号写入。
- 导入时忽略备份中的 `meta.userId`，写入当前账号的 `userId`；不得因导入把账本标记为其他账号。
- v1.0 导出的备份仍然兼容；v1.1.1 不改变备份版本号，避免用户旧文件无法恢复。

### 8.4 关键约束

- 一个账目只能属于一个分类；分类删除必须先迁移账目。
- 金额 > 0；输入与存储均使用整数分。
- 统计按 `occurred_at` 的本地日期归月；跨时区旅行时按当前浏览器时区展示。
- 软删除记录不参与统计，但保留在 IndexedDB 中。
- `qingji-u-<userId>` 之间不得互相读取；切换账号只能通过重新打开对应数据库，不允许在查询中混用。
- v1 不包含转账、账户、预算表；v1.1 通过 schema 版本升级新增，需提供迁移逻辑。
- 认证服务端只保存账号与会话数据；**不得**为了「以后方便」把账目、分类或备份文件上传到认证服务端。
- 旧库 `qingji` 在迁移成功后可保留 30 天；期间只读，不参与当前账号统计。

### 8.5 认证服务端数据模型

```text
user（用户）
  id                 UUID PK
  username           TEXT        展示用，保留大小写
  username_key       TEXT        唯一索引；NFKC + lower 后的判重键
  password_hash      TEXT        Argon2id / bcrypt，含算法参数与盐
  recovery_code_hash TEXT        可空；P1 恢复码
  status             TEXT        active | disabled
  created_at         INTEGER
  updated_at         INTEGER
  last_login_at      INTEGER
  failed_attempts    INTEGER     连续失败次数
  locked_until       INTEGER     可空，限流锁定截止时间

session（会话）
  id_hash            TEXT PK     会话 ID 的哈希，不存明文
  user_id            UUID FK
  created_at         INTEGER
  expires_at         INTEGER     默认 30 天
  revoked_at         INTEGER     可空
  ip_hash            TEXT        可空，脱敏存储
  user_agent_hash    TEXT        可空

auth_attempt（限流/审计，可用 Redis 替代）
  id                 UUID PK
  username_key       TEXT
  ip_hash            TEXT
  action             TEXT        register | login | recover
  success            BOOLEAN
  created_at         INTEGER
```

**约束**
- `username_key` 唯一索引；并发注册由数据库唯一约束兜底。
- 密码与恢复码只存哈希；任何接口都不返回哈希。
- 会话过期或修改密码后失效；服务端支持按用户吊销所有会话。
- 失败记录保留 90 天用于安全审计，不包含密码或恢复码。
- 认证数据库独立于账本存储；备份认证数据库时使用加密备份。

### 8.6 认证 API 契约（建议）

| 方法 | 路径 | 请求 | 成功响应 |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | `{username, password}` | `201 {user, recoveryCode?}` + `Set-Cookie` |
| POST | `/api/auth/login` | `{username, password}` | `200 {user}` + `Set-Cookie` |
| POST | `/api/auth/logout` | 空 | `204`，吊销当前会话 |
| GET | `/api/auth/me` | 空 | `200 {user}`；未登录 `401` |
| POST | `/api/auth/password` | `{currentPassword, newPassword}` | `204`，吊销其他会话 |
| POST | `/api/auth/recover` | `{username, recoveryCode, newPassword}` | `204`，吊销全部会话（P1） |
| POST | `/api/auth/recovery-code` | `{password}` | `200 {recoveryCode}`（P1，新码只展示一次） |
| DELETE | `/api/auth/account` | `{password, usernameConfirm, deleteLocalData?}` | `204`（P1） |
| GET | `/api/auth/csrf` | 空 | `200 {csrfToken}` + Cookie |

**统一要求**
- 所有响应使用同一错误结构：`{ error: { code, message } }`；不返回堆栈或数据库错误。
- Cookie 属性：`HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=2592000`。
- 失败限流返回 `429` 与 `Retry-After`。
- `user` 对象只返回 `{id, username, createdAt}`，不含密码哈希、恢复码、会话。
- 注册/登录请求体大小限制（如 16KB），拒绝多余字段。

| 可访问性 | WCAG 2.1 AA：键盘可操作、正文对比度 ≥ 4.5:1、焦点环清晰、屏幕阅读器可用、表单错误与字段关联、不单靠颜色传达信息；粉色底上禁止小号白字 |
| 国际化 | v1.1.1 仅简体中文 + CNY；用户名支持中文；文案与日期格式预留本地化结构 |
| 可维护性 | 静态前端 + 独立认证 API，可回滚；认证数据库加密备份；错误监控与日志不含密码、恢复码、Cookie；发布前跑多浏览器冒烟与安全测试 |

**周记账习惯用户占比** = 当周记账天数 ≥ 5 天的用户 / 当周活跃用户。

## 附录 B：文案规范

- **语气**：平静、简洁、尊重；像一位不评判的朋友。
- **避免**：感叹号堆砌、「又超支了」「你怎么又…」等指责性表达。
- **超支**：使用「本月餐饮已超出预算 ¥86」，而非「超支警告！」
- **空状态**：给下一步动作，如「今天还没有记账，记一笔吧」。
- **删除/清空**：说明后果与可恢复性，如「删除后 5 秒内可撤销」。
- **数据说明**：直接、不吓人，如「数据保存在当前浏览器，建议定期导出备份」。
- **注册说明**：「只需用户名和密码，不收集手机号 / 邮箱」；不要写成「免费注册，畅享云同步」。
- **登录失败**：统一「用户名或密码不正确」，不提示「用户不存在」。
- **登录与同步**：「登录不会同步账目；换设备请先导出，再在新设备导入。」
- **忘记密码**：「没有恢复码就无法自助找回，请妥善保存。」
- **退出登录**：「退出后本机账本仍保留，重新登录即可继续使用。」
- **注销账号**：「注销后账号无法恢复；本机账本可选择保留或删除。」
- **金额格式**：`¥1,234.50`；输入框内不出现负号与千分位。

## 附录 E：页面与路由清单（v1.0 + v1.1.1）

| 页面 | 路由 | 说明 |
| --- | --- | --- |

**认证门禁**
- 未登录访问 `/`、`/record`、`/stats`、`/settings/*` 时重定向到 `/login?next=<encoded-path>`。
- 登录后回到 `next`；`next` 只允许站内相对路径，禁止开放重定向。
- 已登录访问 `/login`、`/register` 时重定向到 `/`。
- 认证页不加载账本数据、不显示底部导航。
